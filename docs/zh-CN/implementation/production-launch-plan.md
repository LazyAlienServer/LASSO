### 需要继续推进的缺口

P02源码已校验显式production/issuer/context/秘密/Cookie/Flyway/health及持久RSA，并在迁移后检查安全epoch/管理员/ACTIVE客户端，见[实现记录](production-startup-gates-2026-10-07.md)。这不证明目标TLS/代理/Secret保管或正式域名所有权。参考持久撤销仅保证已接受任务恢复，提交前崩溃仍可丢失，生产保留/重放/keyrotation未验。hint/session/授权/审计增长、目标容量、客户端URI、通知和备份输入仍未齐。临时证据不等长期发行保管。

## 2. 上线范围与任务约定

- V1用户名密码，无MFA/邮箱上线要求；SSO管身份、账号生命周期和服务资格，消费方管业务权限与本地近期密码门禁。
- 初期单实例BFF重启结束业务登录，再顶层走SSO；跨重启保登录、多实例SDK不作为本次任务。
- `SERVICE_ACCESS_CHANGED`延期；P12仍需查询补偿/对账/主动刷新及一分钟观察拒绝要求，Logout不代资格同步。
- 所列模块是任务推进位置，不表示所有模块都需新增实现；优先既有配置，只修验收暴露的实际缺口。
- 完成须有负责人、版本/日期、命令和证据位置。外部任务用消费方/运维回传结果，参考BFF通过不能代勾。
- 输入和负责人未齐不虚构日期，依赖完成再开放流量。提交/推送/远程发布/生产库及部署执行仍需对应明确请求。

## 7. 执行顺序与并行

```text
P01 → P02/P03/P04/P05（本地补齐，互不依赖可并行）
P01 → P06 → P07 → P08 → P09/P10（目标环境）
P03 + 目标输入 → P11 → P12（各消费方，外部负责）
P05 + 目标环境 → P13；P06–P13 → P14
P02–P14 → P15 → P16 → P17 → P18 → P19
```

下次推荐先做 **P03可靠撤销操作恢复**，再P04核心UI与人工流程。P02源码实现/测试已完成，目标环境待验；同步收P01输入。P06以后需目标环境，P11/P12需消费方证据；正式消费方不能略自己的任务。只对P01声明首发范围的适用任务设门禁，拓扑改变影响适用性，不改历史事实。
