# 管理员操作：逐项步骤

[目录](README.md) · [English](../en/administrators.md) · [用户](users.md) · [API](api.md) · [维护](operations.md)

## 共用前提与导航

**位置：SSO canonical HTTPS浏览器；操作者：当前唯一SSO管理员。** 完成bootstrap强改后用新密码登录。管理写入对话框填写**管理员自己的密码**，不是目标用户密码；前端先近期认证再执行操作。API直调必须完成相应认证/CSRF/同源步骤。原因填写非秘密工单引用和处理结论。

| 操作 | 流程 |
| --- | --- |
| 查用户/墓碑；freeze/unfreeze；强制下线 | A01–A03 |
| 人工核验/签发恢复凭据 | A04 |
| 新client；编辑；禁用/启用；secret rotation | A05–A08 |
| 注销hold/release；审计/安全事件 | A09–A10 |

管理员自身/另一管理员目标的高风险动作按接口拒绝；唯一管理员失去登录用[离线reset](operations.md)。管理权限不授LASLOG平台角色或游戏准入。一次性结果关闭/Escape/离页清除，不从审计找回明文。

## A01 查用户与已删除墓碑

**前提：** 有目标UUID或当前用户名；需要读信息，不先执行写入。

1. 打开 `/admin/users`，搜索UUID/用户名/显示名，选择状态并“筛选”。优先UUID消除同名显示混淆。
2. 选择左侧账号；核详情顶部UUID、当前名、身份状态、管理员标记。
3. 查看凭据状态、活动会话/授权数、注册/改密/锁定时间；分页时保留过滤条件，必要时返回上一页。
4. 已删除者选择“已删除”筛选；墓碑凭据可能显示“无凭据”、时间“不适用”，不能据空值推断数据库损坏或可重新启用。

**预期：** 读到准确目标，墓碑无恢复/冻结写按钮。**失败：** 空列表先清过滤/核UUID，404由负责人查目标记录，不创建同UUID替代；401重新登录，403核SSO管理员身份，不套业务管理员。

## A02 冻结或解除冻结

**预期：** 读回FROZEN/ACTIVE及对应审计；解冻不恢复已结束的会话或授权。

**前提：** A01核目标，非自身/管理员/已删除；有冻结或解冻的依据。

1. 正常目标点击“冻结账号”，冻结目标点击“解除冻结”。
2. 读范围说明和显示的用户名/UUID；填写原因及当前管理员密码，点击“确认执行”。
3. 成功页面刷新：冻结应为FROZEN、原会话/授权结束；解冻为ACTIVE，但旧登录/授权不会恢复。
4. 按A10查对应审计；与受影响站点确认所需的账号准入拒绝。SSO结果不是已经踢掉所有游戏连接的证明。

**失败：** 当前密码/近期认证失败重新认证，状态冲突刷新重查。网络不确定先查状态/审计，不能为得到“成功”提示重复扩大操作；不通过SQL冻结或解冻。

## A03 强制下线

**预期：** 目标用户SSO会话/授权结束，生命周期不变，并存在对应管理员审计。

**前提：** A01目标允许操作，明确要结束该用户全部SSO会话和授权；它不是冻结。

1. 点“强制下线”，核对UUID和全会话影响。
2. 填原因/管理员密码，确认一次。
3. 刷新详情核活动状态；账号仍保原生命周期，用户可在资格允许时重新登录。
4. A10核ADMIN_USER_REVOKE_SESSIONS结果；消费方Back-channel异步投递失败按[排障](troubleshooting.md)，不恢复旧登录。

**失败：** 自身/管理员目标走离线维护；超时核已提交状态，不把通知未送达误认为SSO事务失败。

## A04 人工核验、签发及交付恢复凭据

**前提：** 普通ACTIVE目标，无可用自助恢复方式；签发前完成独立身份核验。

1. 通过既有联系渠道收最小恢复请求，核当前名/稳定UUID，将敏感沟通转已验证的私密渠道。
2. 用至少两项独立依据对照既有可信记录，记录依据引用/结论/操作者。公开群昵称、单张截图、公开资料或IP不足；核验不成立不签发。
3. A01选准确目标，点击“签发恢复凭据”；填核验工单原因及管理员密码，确认。
4. 私密保存一次显示的凭据/到期时间并在30分钟内交给已核验本人；点“我已保存，关闭”。工单只记requestId/audit/时间/交付渠道引用，不记明文。
5. 本人按U08设置自己的新密码，正常登录；通过结果/审计核完成，不询问新密码。其他未用普通码按现有策略处理。
6. 交付丢失/过期时先核已签发状态，由授权操作者明确**重新签发**，会废旧未用人工凭据；同key replay不重显秘密。不可用码不从DB取回。

**预期：** 仅一次、限时凭据，签发审计留存，用户自行改密。**失败：** 管理员/冻结/已删除目标按服务规则拒绝；签发成功但明文不可见不等“未执行”。不要复制用户密码/恢复码到工单。

## A05 创建OIDC客户端并交付配置

**前提：** 对接方确定公共origin、精确callback/post-logout/Back-channel、scope/audience及环境；对接后端可私密保存secret。

1. `/admin/clients`点“新建客户端”；可选填写独立clientId（不填自动生成），填名称和FIRST_PARTY/REVIEWED_PARTNER类型。不得把未审核站点标第一方。
2. 回调地址每行一个、至少一个，退出地址可选每行一个；填资源audience每行一个、至少一个，以及可达Back-channel地址。当前UI创建scope固定openid profile，不提供任意scope选框。
3. 核scheme/host/port/path/大小写；生产审查HTTPS精确地址，无通配符/fragment/userinfo。先核网络可达，不把样例8088自动当LASLOG。
4. 填原因和管理员密码，点“创建”。一次性对话框私密保存clientId/secret，交付只给服务端；点“我已保存，关闭”。
5. 重开“详情”核类型、URI、scope、audience、configVersion；secret不会再次出现。对接方执行[接入](integration.md)，确认后记录client登记/消费版本。

**预期：** client创建200、独立secret一次；合作方consent适用。**失败：** 创建无通用幂等保证，响应丢失先按输入clientId/名称查列表；若client已存在但secret丢失，按A08轮换，不反复创建重复client。

## A06 编辑客户端配置

**预期：** 读回完整提交配置及当前configVersion，实际撤销结果已记录。

**前提：** 对接方与运维准备变更窗口；保存旧非秘密配置、客户端版本及受影响路径。

1. 在列表“详情”核clientId，再点“编辑配置”；ID不能改。
2. 页面预填全组设置；修改目标字段并检查未修改的URI/audience没有被清空。API PATCH同样是整组设置，非任意局部merge。
3. 填原因/管理员密码，点“保存修改”。
4. 核新的configVersion及是否revocationTriggered；实际服务代码决定撤销范围，不以页面笼统提示推定每种改动都撤销。
5. 对接方部署对应配置，测试新登录/刷新/退出/旧无效URI拒绝；有撤销时用户新登录，不复活旧授权。A10保存脱敏结果。

**失败：** 400逐项核URI/scope/audience；响应不确定先详情核现值/version。恢复旧配置也是一次新变更，不回写历史version或secret。

## A07 禁用或启用客户端

**预期：** 状态与动作一致；禁用时认证拒绝，启用可新建授权，不恢复已撤销授权。

**前提：** 已确认clientId、故障/安全/维护原因及影响的所有用户。

1. “详情”中选择“禁用客户端”或“启用客户端”。
2. 核对话框目标，填原因/管理员密码，确认。
3. 禁用后列表筛“已禁用”，核DISABLED；既有client授权被撤销，新认证应拒绝。
4. 修复完成后启用，核ACTIVE，执行一次全新登录/刷新验证。旧secret（若已轮换）、旧授权、旧consent不会被恢复。

**失败：** 未找到可用client先读详情/审计；超时先核状态，不反复toggle。启用不是绕过未处理的配置或对接安全问题。

## A08 轮换客户端secret

**预期：** 新secret已私密安装，旧secret认证拒绝，用户重新建立授权。

**前提：** client对接方已准备停止写入/更新secret/重启，且知道单把active secret无双密钥宽限期。

1. 保存当前clientId、configVersion、对接部署修订；约定维护时间，必要时先关闭该站入口。
2. “详情”点“轮换密钥”，读旧secret及全部client授权将失效的影响；填原因/管理员密码确认。
3. 私密保存一次性新secret，交给对接后端配置，关闭对话框。不要写到浏览器构建、Git或命令参数。
4. 对接方安装新secret并重启所需进程；验证新登录/刷新，旧secret在隔离负例中拒绝，用户重新登录。
5. A10核rotation审计/configVersion。清理无效secret副本，恢复开放。

**失败：** 同key replay只能确认操作已发生，不返回secret。新secret丢失时协调再次轮换，不能恢复旧secret；网络故障不自动反复换key。

## A09 注销暂缓与释放

**预期：** HELD/PENDING读回与动作一致，原executeAfter保持；暂缓不恢复资格。

**前提：** 有争议/保留依据，核用户UUID、申请requestId和原executeAfter。

1. `/admin/deletion-requests`筛PENDING或HELD，按用户ID/申请时间定位，核待操作申请不是另一次历史记录。
2. PENDING点“暂缓”；填内部原因、无敏感信息的用户可见摘要、未来不超过90天的截止、管理员密码。
3. 确认后核HELD/holdUntil及原executeAfter，安排复查。页面时间输入按浏览器本地时区转换为ISO；核时区。
4. 解除时HELD点“释放”；核原因、原executeAfter及当前时间，填管理员密码确认。
5. 核恢复PENDING；**不会重新起算30天**，已过原期限时下一轮后台可立即执行。本人可按U11取消PENDING/HELD。

**失败：** hold/release无Idempotency-Key保证，超时先查状态/审计；EXECUTED/DELETED不能复活，不能SQL修改执行时间或靠延长hold绕策略。

## A10 检索审计和安全事件

**前提：** 管理员读访问，有目标ID/事件/时间范围；不需要为读强行改变密码证据。

1. `/admin/audit`选“管理员操作”或“安全事件”。
2. 管理员事件选action/targetId；安全事件选type/severity/userId。选择最近1小时/24小时/7天或手填本地时间，核时区后“筛选”。
3. 对照目标、操作者、UTC事件时间、requestId和SUCCESS结果；同action邻近事件不代表同一提交，按ID关联。
4. 下一页保留过滤；需重新搜时清cursor。安全事件REFRESH_TOKEN_REUSE_DETECTED先调查同会话并发/实际泄漏，不故意重放Token制造指标。
5. 工单保存最小事件引用/结论，不导出所有个人资料；原始日志/秘密不附公开issue。分页规则见[API](api.md)。

**预期：** 能关联具体操作与状态变化。**失败：** 空结果先核kind/时间/ID，不把无记录视为写成功或失败；DB不可用转运维，未完成一次性输出不是审计可找回秘密。

## 执行结果不确定的收尾

1. 保留页面错误/UTC时间/requestId，不保密码或结果秘密。
2. 先读目标状态、configVersion及审计，判断是否提交；不能靠重复写制造状态一致。
3. 需要重发/再轮换时执行一次明确的新操作，记录与前次关系。
4. 403先核管理员本身的会话/近期密码/CSRF，不能借另一用户身份绕过；单一管理员不可用走离线维护。
