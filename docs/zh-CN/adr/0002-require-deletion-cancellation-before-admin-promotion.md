# 提升管理员前必须取消有效注销申请

状态：产品决策于 2026-10-02 确认；S4 于 2026-10-04 实现并通过 PostgreSQL／命令 fixture 验证，真实交互进程与生产验收待完成。

英文对应：[Require deletion cancellation before SSO administrator promotion](../../adr/0002-require-deletion-cancellation-before-admin-promotion.md)。

## 决策

存在有效 `PENDING` 或 `HELD` 注销申请的账号不得晋升 SSO 管理员。账号所有者须先通过已有认证取消流程取消申请，再由主机操作员重试 bootstrap 命令。

拒绝不改变管理员身份、密码凭据、注销状态或既有安全状态。命令说明先取消并失败退出，晋升不隐式取消或释放暂缓。

## 考虑过的方案

- 晋升时自动取消：拒绝，主机治理动作不应静默覆盖账号所有者的删除请求。
- 先晋升、删除任务以后取消：拒绝，注销限制与强制改密可能在任务运行或临时密码到期前互相阻塞。

## 后果

- 晋升事务内、角色／凭据变更前检查账号生命周期与有效注销请求。
- 与申请、取消、执行按一致锁序串行化。申请先提交则晋升拒绝；晋升先提交则后续申请按管理员禁止注销规则拒绝。
- 终态请求历史不阻止符合其他条件的账号；冻结或删除账号仍不具备晋升资格。
- 验收覆盖 PENDING、HELD、无有效申请、已取消历史及 PostgreSQL 受控竞争。
- 最初确认仅定义规则，不将实现静默加入五项 P1 范围；S3 完成后用户另要求推进 S4。业务代码与生产部署仍不由本决策授权。

## 实现证据 — 2026-10-04

- 晋升保留维护 advisory lock，先锁 ACTIVE 用户，再锁／检查其 PENDING/HELD 请求，随后才进入用户名、密码、角色和安全状态变更，沿用 S3 用户优先锁序。
- 门禁按有效状态判断，不按日期放行：已到期 PENDING、暂缓到期但仍 HELD 都拒绝；释放暂缓仍是 PENDING，不等于取消。已取消历史不阻止合法 ACTIVE 账号，新有效申请仍阻止。
- 错误码 `DELETION_CANCELLATION_REQUIRED`。命令提示账号所有者先取消、操作员再重试，不输出成功结果并继续抛错。Console 测试证明两次密码缓冲清零，不证明真实 shell 退出码或隐藏输入演练。
- 完整行快照验证拒绝不改角色／哈希／凭据版本、请求、资格版本、恢复状态、会话、授权、审计／事件／outbox；成功重试保留已取消历史并继续既有安全撤销／审计。
- PostgreSQL 申请／晋升／取消／执行／冻结受控交错及真实 SQL 审计失败验证状态重检／回滚；多个合法维护操作竞争仍只产生一个管理员。
