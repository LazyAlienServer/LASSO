# LAS SSO 第一版 UI 流程规格

- 状态：实施前低保真规格
- 目的：冻结影响认证、安全和 API 的交互，不规定最终品牌视觉
- 依赖：[API 契约](../architecture/api-contract.md)、[OIDC 与 BFF 契约](../architecture/oidc-and-bff-contract.md)、[实施就绪度](../implementation/implementation-readiness.md)

## 1. 设计原则

- 页面始终明确当前是在 LAS SSO 还是某个业务网站；有 OIDC 上下文时显示“正在登录到 {clientName}”。
- 不在浏览器页面、URL、前端日志或存储中展示 Token、Authorization Code 或内部错误。
- 一次性恢复码、人工恢复凭据和 Client Secret 只显示一次，离开页面后不可重新获取。
- 账号不存在和密码错误使用同一登录提示；危险操作说明实际影响范围。
- “退出当前应用”和“退出所有应用”使用不同文案、按钮层级和确认说明。
- 所有流程支持键盘操作、可见焦点、正确 label、错误摘要和屏幕阅读器状态通知。
- 第一版以中文为主，文案不可把 SSO 账号状态与 LASLOG 的业务封禁/白名单混为一谈。

## 3. 核心流程

### 3.1 业务网站登录

```text
业务网站点击登录
  -> BFF 保存 state/nonce/PKCE/returnTo
  -> 顶层跳转到 SSO
  -> 无有效 SSO 会话：显示登录页
  -> 有有效 SSO 会话：跳过密码页
  -> 第一方直接继续；合作方必要时显示 consent
  -> 回到 BFF callback
  -> BFF 建立本地会话
  -> 回到已校验的站内 returnTo
```

登录页只显示经过服务端登记的 `clientName`，不读取查询串中的任意站点名称或 Logo。OIDC 事务过期时显示可恢复错误，并提供“返回应用重新登录”，不能尝试使用失效的原始请求。

### 3.2 注册与恢复码

```text
注册表单
  -> 完成 ALTCHA
  -> 创建账号
  -> 一次性显示恢复码
  -> 用户下载/打印或复制
  -> 明确确认已保存
  -> 进入登录或返回原 OIDC 流程
```

确认框不能宣称服务端能够再次显示旧码。若用户丢失页面但仍知道密码，应提示登录后重新生成；不知道密码时只能走人工恢复。

### 3.3 密码恢复

```text
输入精确大小写用户名 + 恢复凭据
  -> 建立 10 分钟受限恢复会话
  -> 设置新密码
  -> 撤销全部旧会话/授权，消耗本次恢复码
  -> 清除恢复会话
  -> 返回普通登录页
```

失败页面不区分用户名不存在、恢复码错误、已使用或已过期。用户名输入旁必须明确提示大小写敏感。

### 3.4 近期认证

```text
用户发起敏感操作
  -> 服务端返回 RECENT_AUTHENTICATION_REQUIRED
  -> UI 要求重新输入当前密码
  -> POST /api/v1/me/reauthentication
  -> 成功后旋转会话 ID并返回原操作
  -> 原操作必须由用户再次确认/提交
```

近期认证成功不能自动执行此前失败的危险写操作，避免过期页面或重复提交造成意外修改。

### 3.5 退出

- 业务页面的“退出当前应用”先清除当前 BFF 会话，即使 SSO 暂时不可用也应立即退出本应用；之后在后台尽力撤销当前授权。
- “退出所有应用”明确说明会退出 LASLOG、AlienCommon 和其他已登录服务；当前 BFF 先清理本地状态，再顶层跳转 SSO 完成全局退出。
- 全局退出结果页可以提示部分应用仍在异步接收通知，但不能让通知失败恢复已撤销的 SSO 会话。

### 3.6 注销

申请页必须显示：30 天等待期、立即全局退出、到期删除 SSO 凭据与资料、业务系统历史内容可能按各自规则保留。申请需要请求内密码。

等待期登录后只进入受限页面，可取消注销或退出，不能继续 OIDC 授权。若注销处于暂缓，页面显示“正在人工处理”和可公开的原因摘要，不泄漏管理员内部备注。

### 3.7 管理员危险操作

冻结、人工恢复、Client 变更和注销暂缓都需要：

1. 显示目标的 UUID 和精确大小写用户名/客户端 ID；
2. 填写原因；
3. 必要时完成近期认证；
4. 显示影响范围；
5. 提交后展示审计事件或 request ID。

禁用客户端和缩小 scope/audience 必须明确提示会撤销现有授权及会话。Client Secret 轮换使用短维护窗口：新 Secret 创建后旧 Secret 立即失效，页面必须先要求管理员确认目标 BFF 已进入维护/可立即部署状态。

## 4. 通用页面状态

每个调用 API 的页面至少设计并测试：

```text
initial
loading
success
empty
validation_error
authentication_required
recent_authentication_required
forbidden
rate_limited（显示 Retry-After）
state_conflict（重新读取服务端状态）
service_unavailable（可重试但不误称账号被封禁）
```

按钮在请求进行中防重复提交，但不能只依靠前端防重；一次性操作仍使用服务端幂等和事务约束。

## 5. 视觉设计可以后置的内容

以下内容不阻塞后端和低保真 UI 开发：

- 最终 Logo、插画和动效；
- 完整品牌色与深色模式；
- 复杂账号首页仪表盘；
- 合作方自定义主题；
- 非关键响应式细节。

在进入公开测试前，至少确定基础设计令牌、表单/按钮/提示/对话框组件、窄屏布局和 WCAG 2.2 AA 目标，并完成登录、注册、恢复、全局退出和管理员危险操作的浏览器走查。

## 6. 线框验收清单

- 直接访问和来自业务网站的登录上下文都画出。
- 所有密码字段说明用途，不提供显示秘密的日志/遥测。
- 用户名输入和展示保留大小写，并明确登录大小写敏感。
- 一次性秘密页面包含保存动作、不可找回说明和离开确认。
- 当前退出与全局退出不会被用户混淆。
- 冻结、业务封禁、注销等待和 SSO 故障使用不同文案。
- 临时密码、恢复会话、OIDC 事务和近期认证过期都有恢复路径。
- 管理员操作同时显示人类可读名称与不可变 UUID/client ID。
- 键盘顺序、焦点、错误摘要、色彩对比和屏幕阅读器通知已说明。
